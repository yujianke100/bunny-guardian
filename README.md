# 兔兔守护者 · Bunny Guardian

自托管的**个人健康档案 + 可核对来源的医学知识库**，并带一个**权限受限的在线助手**。

项目的立意取自《史记·扁鹊仓公列传》中的**诊籍**：淳于意把每次诊治的脉证与预后都记录下来，
是现存文献所见最早的医案记录。这个项目做的事情与此相同——**按人归档的病历，加上可追溯的依据**。

> 本项目是**软件**。使用者的健康数据存在**另一个私有仓库**里，两者严格分离（见下文「两仓模型」）。

## 它解决什么问题

市面上的经期/健康 App 有三类问题：数据在别人服务器上、结论没有出处、AI 可以随意改动记录。
兔兔守护者的做法是：

| 原则 | 具体做法 |
|---|---|
| **数据在自己手里** | 全部落在一个目录里（SQLite + Markdown），可以 `cp -r` 备份、用 git 做版本 |
| **每条医学事实都有出处** | 知识库文档逐句标注 `[来源: URL]`，并区分「指南原文」与「一般性解释」 |
| **推断必须标明是推断** | 周期/排卵预测给出区间与置信度，并声明不能用于避孕或确诊 |
| **AI 不能直接改数据** | 助手只能提交**待批准提案**，人工批准后才写入，且每次调用都留审计 |
| **部署不侵入系统** | 全部在 `$HOME` 下，systemd 用**用户单元**，安装**不需要 root** |

## 功能

- **经期记录**：日历、经量/症状日志、周期统计与阶段推断
- **周期环**：钟表式圆环，指针指向「今天」，两套视角可切换
  —— 医学分期（月经期/卵泡期/排卵期/黄体期）与通俗说法（月经期/安全期/易孕期）
- **疾病档案**：一种疾病一份档案，挂病程时间线（就诊/检查/用药/手术/症状变化）
- **就医记录**：机构、科室、诊断、处置、费用
- **医学知识库**：带来源的文档，**以 SQLite 为唯一数据源**；中文检索走进程内倒排索引
  （不扫文件、不依赖 FTS 分词器），渲染与检索都在数据库上完成
- **化验单看懂**：上传照片 → 自动压缩 → 交给视觉模型逐项对照参考范围解读
- **在线助手（可选）**：7 个白名单工具，只读查询 + 提交提案；外发内容经过隐私围栏
- **多用户与权限**：管理员/成员，按模块（经期/疾病/就医/知识库/问答）设 无/看/改
- **数据同步**：目标 GitHub 仓库在**网页里配置**（含分支、定时开关、是否附带 SQLite 快照），
  一键「立即同步」即导出 → 提交 → 推送；数据库快照可用于完整恢复
- **数据都在一个文件里**：SQLite 存结构化记录、知识库文档与索引；
  Markdown 只是导出给人看、给 git diff 的产物

## 快速开始

需要 Python 3.11+ 与 systemd（Linux）。**不需要 root**。

```bash
git clone <this-repo> ~/bunny-guardian && cd ~/bunny-guardian
sh deploy/install.sh                 # 建目录、装依赖、装用户单元、启动
```

首次启动会在日志与数据目录里打印初始管理员密码。让服务在注销后继续运行（一次性，需要 root）：

```bash
sudo loginctl enable-linger $(id -un)
```

外网访问：应用只监听 `127.0.0.1:9810`，用你自己的 nginx/Caddy 反代即可，
示例见 `deploy/nginx-vhost.conf.example`。**注意问答是 SSE 流式返回，反代要关闭 buffering。**

想让助手可用的额外两步：

```bash
sh deploy/setup-node.sh              # 用户级 Node + pi
# 网页「管理 → 智能体权限」生成令牌，写入 ~/.config/<slug>/agent.env（600）
sh deploy/pi/agent.sh -p "现在该注意什么？"
```

## 数据放在哪

默认落在**项目文件夹内**：`<项目>/data/`（`data/` 与 `tools/` 已在 `.gitignore` 中）。
备份或迁移 = 拷走整个文件夹或那一个 `.db` 文件。也可以配置到任意路径：

```sh
DATA_DIR=/srv/bunny-guardian-data sh deploy/install.sh
```

## 三个仓库（重要）

```
┌──────────────────────────────┐
│ bunny-guardian（本仓库，表的家）│   只放「表」：健康档案本身
│ app/ deploy/ scripts/        │   不含任何个人数据，可以开源、可以分享
│ templates/kb/（起步模板）     │
└──────────┬───────────────────┘
           │ 读取/写入
           ├───────────────────────────────┐
           ▼                               ▼
┌──────────────────────────┐   ┌──────────────────────────────┐
│ 你的数据仓库（私有）        │   │ ex-bunny-guardian（可选，私有）│
│ docs/经期记录/            │   │ 「里」：情侣空间 / AI 跑团      │
│ docs/疾病档案/            │   │ 以扩展形式叠在表上运行          │
│ docs/就医记录/            │   └──────────────────────────────┘
└──────────────────────────┘
```

- **表**（本仓库）就是健康档案应用本身，能单独跑：装完 `deploy/install.sh` 即可用。
- **里**（`ex-bunny-guardian`）不属于本仓库：它是**扩展**，通过 `BG_EXTENSIONS`
  指向它的扩展目录挂进来（见 `app/extensions.py` 与 `app/README.md`）。
  两个仓库都不重复对方的代码：表怎么改，里都不用跟着抄。
- **数据仓库**是你的私人档案，**不应公开**；应用通过 `BG_KB_DIR` 指向它。

挂上里的服务器大致长这样：

```sh
~/bunny-guardian/            # 表：本仓库的检出
~/ex-bunny-guardian/         # 里：扩展仓库的检出
~/kb/                        # 数据仓库（BG_KB_DIR）
# 让表带上里：
BG_EXTENSIONS=$HOME/ex-bunny-guardian/extensions
```

没有数据仓库也能跑：`deploy/install.sh` 会用 `templates/kb/` 建一个空的起步知识库。
不配 `BG_EXTENSIONS` 也能跑：那就是纯粹的表。

```
浏览器 ──HTTPS── 你的反代 ──HTTP── uvicorn 127.0.0.1:9810（用户级 systemd 单元）
                                        │
                    ┌───────────────────┼────────────────────┐
                    ▼                   ▼                    ▼
              SQLite（数据目录）   数据仓库 Markdown     模型端点（可配置）
              · 经期/疾病/就医      · 知识库文档          · 内网自建（推荐）
              · 用户/权限/审计      · 导出的人可读记录     · 或任何 OpenAI 兼容 API
```

## 助手权限模型

助手**不是**一个能随意操作你服务器的通用 agent。它的边界是：

- **工具白名单**：只有 7 个工具（档案概览、记录查询、知识库检索、联网检索、抓取权威来源、
  提交录入提案、查看待批准提案）。内置的读写文件与执行命令工具**不存在**。
- **写入需人工批准**：它只能提交 `pending` 提案，你在网页上点「批准并写入」才会落库。
- **外发内容策略**：姓名、账号、域名、邮箱、具体日期、路径、令牌、内网 IP 在发送前一律抹除；
  端点是公网时还会复核一遍，仍有工程信息就拒绝发送。
- **域名白名单**：只能抓取 ACOG / WHO / NICE / MSD / PubMed / CDC 等权威医学来源。
- **审计与配额**：每次工具调用（含被拒绝的）都留痕，并有每日配额上限。

完整说明与残余风险见 [`docs/agent-permissions.md`](docs/agent-permissions.md)。

## 资源占用

在一台 2 vCPU / 961MB 内存的云主机上实测：

| 组件 | 占用 |
|---|---|
| Web 服务 | 常驻 47–50MB（单元上限 320MB） |
| 助手（按需启动） | 峰值约 110MB，单次回答约 7.5s |
| 模型推理 | 不在本机，走配置的端点 |
