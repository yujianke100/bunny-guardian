# 我的健康档案（数据仓库）

这是**兔兔守护者（Bunny Guardian）**的数据仓库：只放个人记录与医学知识文档，**不放代码**。
系统代码在另一个仓库里，通过 `BG_KB_DIR` 指向本目录的 `docs/`。

> 本仓库应当保持**私有**。个人健康数据属于敏感信息。

## 目录

| 目录 | 内容 |
|---|---|
| `docs/INDEX.md` | 文件地图（入口） |
| `docs/经期记录/` | 周期与症状记录（由网页导出生成） |
| `docs/疾病档案/` | 疾病与病程时间线（由网页导出生成） |
| `docs/就医记录/` | 就诊记录（由网页导出生成） |
| `docs/医学知识/` | 带来源的医学知识文档（人工/助手整理） |

## 两条数据通路

1. **结构化记录**：在网页上录入 → 存 SQLite → 点「导出到知识库」生成 Markdown 并提交到本仓库；
2. **知识文档**：直接以 Markdown 维护，每条事实性陈述标注 `[来源: URL]`。

## 约定

- 每个文档带 YAML frontmatter（`title` / `tags` / `aliases` / `last_updated`）。
- 交叉引用用 `[[相对路径或别名]]`；新增文档后更新 `docs/INDEX.md`。
- 医学知识文档：逐条标注来源，查不到来源的写「（待核实）」，不给诊断结论与药物剂量。
- 提交身份建议与系统仓库保持一致，便于追溯。

## 与系统仓库分离的意义

- 系统可以开源、可以分享；本仓库**永不公开**。
- 备份只需备份本仓库（加上数据目录里的 SQLite 与上传附件）。
- 网页上的「导出」把数据库里的结构记录变成**人能读、git 能 diff** 的 Markdown，
  这样即使软件将来不用了，档案依然可读可查。
