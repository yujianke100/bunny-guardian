# 智能体权限框架

在线智能体的能力边界、强制手段与审计方式。**任何扩大权限的改动都必须先改这份文档。**

## 一、允许范围（与档案主人商定）

| 用途 | 对应工具 | 性质 |
|---|---|---|
| 当前病情询问 | `health_context`、`record_query` | 只读 |
| 病情问答 | `kb_search` + `record_query` | 只读 |
| 月经相关询问与预测 | `record_query(kind=cycle_stats)`、`health_context` | 只读 |
| 数据记录整理归档 | `submit_record` | **写提案**，需人工批准 |
| 联网搜索 | `web_search`、`web_fetch` | 服务端围栏 + 域名白名单 |

## 二、禁止范围（硬约束，不可通过配置放宽）

- 执行任何命令（没有 shell 工具，内置 `bash`/`read`/`write`/`edit` 不在白名单内）
- 直接写数据库（只能提交提案；落库由网页端在人工批准后执行）
- 删除任何记录（接口层没有删除能力）
- 修改医学知识文档、修改代码、执行 git 操作
- 读取账号、会话、令牌（接口只返回摘要字段，不返回 users/sessions 表）
- 访问白名单之外的域名
- 把个人信息带出内网（隐私围栏拦截）

## 三、四道防线

1. **工具层**：`deploy/pi/extensions/health-tools.ts` 只注册上表 7 个工具；会话开始时再用
   `pi.setActiveTools([...])` 收敛一次，`deploy/pi/run.sh` 里的 `--tools` 再做一层白名单。
   模型看不到的工具，它就调不动。
2. **进程层**：`deploy/pi/agent.sh` 用 `systemd-run` 把智能体跑在沙箱里——非特权用户 `bg`、
   `ProtectSystem=strict`、`NoNewPrivileges`、空 capability 集、内存 420MB / CPU 120% /
   单次最长 15 分钟。**唯一额外开放读写的目录是数据目录**：SQLite 的 WAL
   模式在只读挂载下无法打开数据库，而智能体必须读配置（端点与模型名）。模型没有文件或 shell 工具，
   够不到这个目录；记录只能经 API 提交为「提案」。
3. **数据层**：智能体不接触 SQLite 文件，只能调 `/api/agent/*`（见 `app/agent.py`）。
   查询走类型白名单（`cycle_history` / `cycle_stats` / `conditions` / `condition_detail` /
   `visits` / `day_logs` / `search`），**不接受自由 SQL**；返回字段也做了裁剪
   （如就诊记录只给日期/科室/诊断，不给医院名与费用）。
4. **动作层**：一切写入先落成 `pending` 提案，必须在「管理 → 智能体权限」点「批准并写入」
   才会执行，执行结果记入 `agent_proposals.apply_result`。

## 四、联网的两种防护

- **隐私围栏**（`agent.privacy_check`）：外发文本若含账号、显示名、档案主人姓名、
  域名/邮箱、**任何 `YYYY-MM-DD` 形式的具体日期**，或超过 200 字 → 直接拒绝并记录被拒原因。
  目的是防止「她的就诊时间线」被当成检索词送到搜索引擎。
- **域名白名单**（`agent.FETCH_ALLOWLIST`）：只允许 ACOG / WHO / NICE / MSD / PubMed / CDC /
  中华医学会等权威来源。

## 五、审计、配额与总开关

- 每一次工具调用（含被拒绝的）都写入 `agent_audit`：时间、工具、裁决、详情摘要。
  被拒记录是排查提示注入的主要线索，可在管理页查看。
- 每日配额：`web_search` 30、`web_fetch` 40、`propose` 20、`records_query`/`kb_search` 各 120。
  目的是给「被注入的提示词逼着反复刷接口」封顶，次日自动重置。
- 总开关 `agent_enabled`：管理页一键停用后，所有 `/api/agent/*` 立即返回 401；
  令牌可一键全部吊销。
- 令牌：库中只存 SHA-256 哈希，明文仅在生成时显示一次，写入 `~/.config/<slug>/agent.env`（600）。

## 六、已知残余风险

1. **模型本身可能被知识库或网页中的文本带偏**（间接提示注入）。缓解：工具集合受限、
   写入必须人工批准、白名单域名、审计留痕。**没有做到**的是对工具返回内容做语义过滤。
2. **联网搜索的检索词仍会到达搜索服务商**（即使已去掉个人信息）。若这也不接受，
   就自建 SearXNG 或直接关闭 `web_search`（只保留 `web_fetch` 白名单站点）。
3. **人工批准环节的安全性取决于管理页账号**——它等同于写权限，密码与设备安全需要单独保证。
4. 智能体读到的档案摘要**包含健康信息**，会进入 GPU 主机的推理上下文（内网自建模型，
   不出公网）。这是当前架构的前提，请勿改为公网第三方模型。

## 七、模型接入配置（网页可改，密钥单独落盘）

管理 → **模型接入配置**（`/admin/llm`）可以改接口地址、模型名与 API Key，网页问答与智能体共用这一份配置。

| 项目 | 做法 |
|---|---|
| 密钥存放 | 独立文件 `<数据目录>/llm_api_key`，权限 `600`、属主为服务账号；**不写数据库、不进 git** |
| 密钥展示 | 页面只显示后 4 位；接口永不回显全文；审计只记「是否变更」 |
| 写入方式 | 先写临时文件再 `os.replace` 原子替换，避免半截内容 |
| 公网端点 | 默认拒绝保存，必须显式勾选「我了解数据外发风险」；启用后页面常驻红色提示 |
| 智能体取值 | `deploy/pi/run.sh` 调用 `app/llm_config.py models-json` 生成 pi 的模型清单，改配置后下次启动即生效 |

> 换模型端点时必须重新评估隐私边界：公网端点意味着**档案摘要会离开内网**。

### 工具调用的前提

智能体依赖服务端返回**结构化 `tool_calls`**。若端点是不带
`--tool-call-parser` 的 sglang，模型会把工具调用当纯文本输出（实测 `tool_calls: null`），
智能体就只会「念」出要调用的工具而不会真的执行。此时要么换支持函数调用的官方 API，
要么在推理服务上开启对应解析器。

## 八、外发内容策略（红线：智能体/工程信息绝不外发）

用户定下的边界很明确：**档案主人的病情数据发往所配置的模型端点（含公网中转）可以接受；
但智能体自身的信息绝不允许发到那台服务器的 API 上。**

`app/outbound.py` 对所有外发消息做统一处理：

| 类别 | 例子 | 处理 |
|---|---|---|
| 身份信息 | 姓名、账号、显示名、个人域名、邮箱、具体日期 | 一律替换为 `[已隐去]`（任何端点） |
| 工程/智能体信息 | `/opt/bunny-guardian`、`/var/lib/bunny-guardian`、`bg_` 令牌、`sk-` 密钥、内网 IP、集群名、内部项目名、其他仓库名、`deploy/pi/*`、`CLAUDE.md`、站点域名 | 一律替换为 `[已隐去]`；端点为**公网**时再用 `verify_no_internals()` 复核，仍有残留则**拒绝发送**（fail-closed） |
| 健康信息 | 月经统计、疾病名、就诊科室、知识库医学文档 | 允许外发 |

另外两条配套约束：

- **模型名同样来自网页配置**：`run.sh` 用 `llm_config.py current-model` 解析，不写死在脚本里
  （曾因写死内网模型 id，导致配了公网端点后中转返回 404 model_not_found）。
- **智能体的端点检查（警告，不拦截）**：`deploy/pi/run.sh` 启动前调用
  `llm_config.py check-agent-endpoint`，端点为公网时在终端打出黄色警告并继续启动——
  是否使用由用户决定。读不到配置数据库时同样只给「无法确认」警告。
- **降低智能体的外发面（代替一刀切禁止）**：智能体的工作目录指向
  智能体工作目录（由 `deploy/install.sh` 创建，默认 `~/agent`），其中只有一份**净化过的**
  `CLAUDE.md`（源文件 `deploy/pi/agent-context/instructions.md`，不含任何部署路径、
  令牌、主机名或其他项目名）。因此智能体不会加载仓库里那份带路径与配置细节的 `CLAUDE.md`，
  它发给模型的内容只有工作准则、工具说明与对话本身。这一点由冒烟测试静态校验。
- **图片可外发**（用户明确要求）：化验单/检查报告照片经压缩后作为 `image_url` 发送，
  用于病情分析；图片同时在本机归档为附件，不进 git。

## 九、图片问诊

- 入口：问答页「📎 附化验单/照片」，支持 jpg/png/webp/heic，≤12MB。
- 处理：`app/media.py` 用 Pillow 缩放至最长边 1600px、JPEG q82，实测 3000×2000 PNG 可压到原体积的
  十分之一以内；未安装 Pillow 时原样上传，功能不中断。
- 提示词：带图时追加 `VISION_SYSTEM`——要求先逐条抄录图片中的数值与单位、再对照
  《检查项目与参考值》解释、看不清就明说、不给诊断与剂量；并自动补上该知识库文档作为依据。
- 归档：图片存服务器本地并登记为 `attachments(ref_kind='qa')`，可在数据库层面追溯。

## 十、验证方式

`app/smoke_test.py` 中的智能体用例覆盖：无令牌 401、令牌可用、隐私围栏拦截个人信息与日期、
域名白名单拦截、提案不会直接落库、批准后才落库、非法查询类型被拒。
运行：

```bash
BASE=http://127.0.0.1:9814 BG_DB=/tmp/kb-test/x.db python smoke_test.py
```
